# Native CLI без внешнего сетевого доступа: измеренная проверка

2 ноября 2026, Linux. Скрипт `scripts/probe-offline.py` по умолчанию только
показывает план. `--help` и dry run доступны на Linux, Windows и macOS;
`--execute` честно требует Linux, `bwrap` и `strace` и не запускает CLI на
неподдерживаемой ОС. Это отдельный проверочный инструмент; переносимый
рабочий gateway, MCP и установщик не зависят от bwrap.

Успешные пробы использовали реальный установленный ELF Claude Code 2.1.316:
SHA-256 `fd13c70000fec3f2116dfbcbb6121210b4a29328bf0e46210a59dd594a67d824`.
Модель — `nd/qwen3.8-27b@subscription~xhigh`. Кошелёк не использовался.

| Проба | Результат | Время | Фактические запросы gateway | TCP connect в trace |
|---|---|---:|---:|---:|
| `20261102T165413371175Z`, ответ `OFFLINE_OK` | PASS, exit 0 | 3,20 с | 1 | 5 |
| `20261102T165827430393Z`, native `nd-design` и готовый HTML | PASS, exit 0 | 149,47 с | 11 | 22 |

Receipt, stream-json и strace находятся в
`.local/offline-validation/<имя-пробы>/`. В обеих пробах все 14 NeuralDeep MCP
были `connected`; `nd-design` и `nd-workflow` обнаружены в native `init.skills`.
Во второй есть настоящий вызов инструмента `Skill`, Read существующего
изображения и HTML-артефакт: см. `docs/VALIDATION-design.md`. Списки разрешённых
инструментов ограничены только в этих тестовых процессах; отсутствие `Workflow`
в их `init.tools` не является проверкой рабочей функции Workflows.

CLI и его дочерние процессы запускались только после проверки, что новый
kernel network namespace отличается от host и содержит только `lo`.
`bwrap --unshare-net --bind / / --dev /dev` оставляет файловую систему общей:
это доверенный функциональный тест, не sandbox против вредоносного кода.
Неизменяемый четырёхбайтовый заголовок Unix-моста содержит `ND` и номер порта;
разрешены только 8787 и 18790, адрес назначения всегда `127.0.0.1`. Произвольные
домены/IP/порты и shared relay 20171 этим протоколом недоступны.

Host 8787 — рабочий NeuralDeep gateway с прямым upstream transport. Host 18790 —
отдельный защитный proxy Claude. Поэтому кроме kernel namespace проверяется
аудит host guard: внешних соединений со статусом `connected` в обеих пробах
**0**. В strace также **0** успешных и **0** неразрешённых non-loopback connect.
Незавершённый connect и `EINPROGRESS` к внешнему адресу трактуются как
неразрешённый исход и проваливают проверку; они не выдаются за безопасный отказ.
Strace пишет только connect/getsockopt, без payload, env и ключей.

Проверка сохраняет границы policy, версии, хеши источника/бинарника и файлов,
фактические gateway/guard события и namespace identity. В design-каталоге
также есть точная `probe-offline.py.snapshot`; её хеш совпадает с receipt
`f939b90262b9f20bf3ca2e419e549e595ea87a0dd15be7712d84bebcbc274af3`.
Конфигурация дочернего процесса может содержать локальный gateway-токен,
поэтому каталог имеет 0700, JSON-файлы — 0600; эти файлы не предназначены
для публикации.

Ранняя неуспешная проба `20261102T165335778513Z` сохранена: bind `/` дал
`PermissionError` при открытии `/dev/null`, до запуска native CLI. Исправление
— отдельный стандартный `--dev /dev`, с сохранением `--unshare-net` и всех
проверок. Обхода сетевой изоляции не было.

Повторение требует уже запущенных проверенных локальных gateway и guard,
зарегистрированного реального native CLI и сохранённого каталога; скрипт не
обновляет каталог и не запускает launcher внутри namespace:

```sh
python3 scripts/probe-offline.py
python3 scripts/probe-offline.py --execute --timeout 240
python3 scripts/probe-offline.py --design
python3 scripts/probe-offline.py --execute --design --asset /absolute/path/existing.png --timeout 180
```

Последняя команда повторяет локальный skill с готовым изображением; новой
генерации/HTTP-операций MCP в ней нет. Она всё же вызывает модель NeuralDeep
через выбранный ключ. Собственная группа процессов, потоки и Unix socket
удаляются и при таймауте/сигнале. Shared relay, system proxy, ChatGPT и Codex
не изменяются. Полученный PASS относится к указанным bounded-сценариям;
производственный proxy сам по себе не является OS sandbox.


## Окончательно выбранный production-режим

Пользователь явно выбрал настройки и отдельный фильтр без постоянной системной изоляции. После этого обычный установленный wrapper `claude` проверен без bwrap: FILTER_OK, exit 0, 6.722 с; включены Workflow и Skill, подключены все 14 NeuralDeep MCP. Фактический бюджет запроса — 128000; после запуска audit фильтра проверен отдельно: разрешённые внешние соединения не выдаются за нулевой общий счётчик. Receipt: `.local/final-selected-policy/acceptance.json`. Это проверка выбранного режима, а не утверждение о постоянном OS firewall.

Последующий audit выбранного обычного запуска: фильтр разрешил два соединения с `registry.npmjs.org` для существующей интеграции и отклонил обращения к `platform.claude.com` локально. Это не нулевой общий счётчик интернета; ни один запрещённый адресат не был направлен guard во внешнюю сеть. Отдельный receipt: `.local/final-selected-policy/egress-audit.json`. Прямые raw-socket обходы вне изолированного теста этим audit не доказываются; пользователь принял эту границу выбранного режима.
