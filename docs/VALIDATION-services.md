## Найденные несовпадения и сбои

**Правка изображения: исправлена реальная несовместимость с документацией.**
Документация требует multipart `images[]`; сервер вернул HTTP 422 с
`missing body.images`. Адаптер теперь отправляет повторяемое поле `images`.
После изменения один корректный запрос успешно создал и завершил задачу,
скачал PNG 512×512. Визуально исходный синий круг стал красным, как требовалось.
Исходная ошибка сохранена в `service-extra-probes.json`, исправленный запрос
и результат — в `image-edit-corrected.json`. Слепого повторения исходного
запроса не было.

**Аватар: провайдер вернул HTTP 422 `image avatar failed`.** Отправлен
сгенерированный портрет вымышленного взрослого человека, multipart `photo`,
`gender=male`, `style=professional`. Документация не перечисляет допустимые
значения gender/style, ответ не даёт информации для корректировки запроса.
Повторять варианты наугад и объявлять операцию успешной оснований нет.
На момент этой пробы инструмент был доступен и вернул реальную ошибку.
Впоследствии пользователь выбрал отключить только Avatar до подтверждённого
исправления. Для его повторного включения нужен успешный пример провайдера
или уточнение параметров/исправление сервиса; остальные image tools включены.

**Экспорт SRT:** провайдер отдаёт MIME `text/plain`. Адаптер учитывает явно
запрошенный формат при сохранении и создаёт `.srt`, а не `.txt`; сохранённая
первая живая проба имеет `.txt`, содержимое опознано как SubRip. Регрессионный
тест проверяет исправленное расширение. Остальные экспорты также распознаны
по типу: DOCX как Word 2007+, PDF как одностраничный PDF, VTT как WebVTT.

их. Проверка не означает доказательства всех предельных размеров, нагрузочной
устойчивости, качества любой генерации или доступности сервиса в будущем.
