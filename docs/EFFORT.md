# Штатный `/effort` и уровни моделей NeuralDeep

В списке моделей находится один пункт на модель и способ оплаты. В CLI effort
переключается штатным `/effort`, отдельно от выбора модели. Дополнительные
пункты `модель · low`, `модель · medium` и т. п. не создаются.

## Графический переключатель в Claude Desktop

В Desktop 4.4212.0 обычное обнаружение через `/v1/models` загружает список,
названия, описания и признак 1M. Штатное меню effort берёт варианты из
известной модели Claude или явного `inferenceModels[].behavesAs`. Данные
`neuraldeep.claude_effort` доступны через шлюз для диагностики. Desktop не
использует их для меню, а `maxEffort` только ограничивает уже известные
варианты. Поэтому установщик генерирует полный `inferenceModels` из
актуального каталога NeuralDeep. Лаунчер обновляет каталог при запуске.
`./update-models.sh` и `update-models.ps1` обновляют список отдельно.
Desktop загружает новую конфигурацию после полного выхода и запуска.

Для регулируемых моделей используются их собственные профили Claude либо
клиентский профиль `claude-opus-4-8` с пятью положениями. Фактическая
модель и способ оплаты определяются ID маршрута, а шлюз применяет таблицу
effort ниже. У моделей с фиксированной глубиной переключателя нет.
Профиль совместимости влияет на оценку контекста и вывода в интерфейсе.
Название модели содержит её лимит по данным NeuralDeep. Claude Code
использует также отдельные настройки окна автосжатия по ID, а шлюз
учитывает опубликованный лимит вывода.
[Конфигурация Desktop](https://claude.com/docs/third-party/claude-desktop/configuration#inferencemodels).

**В Code работает текстовая команда `/effort <уровень>`.** 3 ноября в
настоящем Desktop Code пользователь отправил `/effort low` отдельным
сообщением. Движок 2.1.309 ответил, что уровень установлен для текущей
сессии. Следующий запрос на Qwen 3.8 27B по подписке ушёл с `low → low`
и вернул `ND_DESKTOP_EFFORT_LOW_OK`. Свидетельство сохранено в
`.local/effort-validation/desktop-text-effort-20261103.json`.

В описании маршрута теперь видны реальные сконфигурированные уровни либо
конкретная причина отсутствия настройки. Короткие метки различают варианты
без reasoning, фиксированную глубину, документированный upstream
переключатель thinking, численный бюджет upstream без подтверждения Hub
и отсутствие опубликованного NeuralDeep параметра. Метка `exp. effort`
означает уровни upstream, принятие которых проверено на API NeuralDeep,
а применение внутри бэкенда остаётся экспериментальным. Эти описания
доступны в локальном каталоге и ответе шлюза `/v1/models`.

У Desktop Code есть отдельный способ задать постоянный effort без меню.
Команда `python scripts/nd.py models show qwen3.8-27b` показывает маршрут,
а аудит печатает его `desktop_id`. В существующем объекте
`modelSettings` файла `~/.claude/settings.json` можно добавить
`effortLevel` к записи этого ID, сохранив её `autoCompactWindow`.
Движок Desktop Code 2.1.309 в изолированной проверке передал
`low`, `medium`, `high`, `xhigh` из такой записи в запрос. Вариант
`max` нельзя задать как постоянное значение, а для моделей, у которых
`xhigh` уже отображается в максимум, достаточно `xhigh`. Этот способ
относится к движку Code. Текущие предпочтения пользователя не изменены.

## Проверка всех маршрутов

```sh
python scripts/audit-effort.py
python scripts/audit-effort.py --execute --missing-history
```

Первая команда проверяет пять штатных значений на каждом маршруте локально,
включая скрытые, и проверяет отказ устаревшего ID. Вторая отправляет запросы
через работающий шлюз по видимым маршрутам с учётом успешных сохранённых
проверок. Без `--missing-history` повторно проверяются все отличающиеся
исходящие параметры на всех видимых маршрутах. Запросы кошелька тарифицируются.

На каталоге 3 ноября проверено 240 сочетаний (48 маршрутов × 5 уровней),
отдельно проверен отказ снятого маршрута. У 44 видимых маршрутов
91 различающаяся комбинация параметров по маршрутам и биллингу.
86 подтверждены сохранёнными ответами, оставшиеся пять прошли через шлюз
3 ноября. Файл `.local/effort-audit/20261103T160827805747Z.json` содержит
помодельную матрицу. Эти пробы подтверждают успешный ответ с отправленным
параметром. Фактическое применение закрытым бэкендом проверяется отдельно.

В дополнительных пробах `qwen3.8-flash-next-ru` приняла и обычные значения,
и намеренно недопустимое. Разброс reasoning-токенов в одиночных ответах
не подтвердил управляемую шкалу. **Решение 5 ноября:** модели добавлены
канонические уровни её семейства `qwen3.8-flash` — low / medium / xhigh
с `effort_status: family-documented-live-accepted` (тот же статус, что у
`gpt-oss-20b`). Основание: живое принятие low/medium/xhigh на обеих схемах
оплаты (повторные пробы 5 ноября —
`.local/effort-validation/flash-next-ru-effort-20261105T125527420947Z/`,
`flash-next-ru-effort-depth-20261105T130346424191Z/`,
`effort-discriminate-20261105T132309613499Z/`) при отсутствии доказательств
обратного. Честная оговорка сохранена в профиле: применение закрытым
бэкендом **не доказано** — лента принимала и заведомо недопустимые значения,
а позитивный контроль на документированной `qwen3.8-27b` показал, что сама
метрика reasoning-токенов не различает уровни
(`positive-control-qwen38-27b-20261105T131910060329Z/`). `reasoning_off_efforts`
(`none`) сознательно **не** унаследован: NeuralDeep документирует, что
`enable_thinking=false` на базовом имени Qwen снимается гейтом и модель
продолжает думать; выключение доступно только `-noreason`-моделям.
Qwen 3.7 Flash и Plus превысили отправленные
`thinking_budget=32` и `1024`, а `enable_thinking=false` оставил reasoning
в ответе. Эти флаги не подключены к `/effort`. Дополнительные пробы
переключателей остановлены после 180-секундного таймаута Gemma, без вывода
о поддержке её флага. Наблюдения сохранены в
`.local/effort-validation/exploratory-controls-20261103.json`.

Оригинальный CLI 2.1.316 также запущен на каждом из 44 видимых маршрутов
с каждым из пяти значений `--effort`, всего 220 запусков. Локальный
регистратор подтвердил исходный маршрут и точный `output_config.effort`
во всех 220 запросах. Это отдельная проверка клиента без расхода квоты.
Отчёт `.local/effort-validation/20261103T161007854532Z/all-routes-native-loopback.json`.

Шлюз принимает `output_config.effort` Claude и переводит его в настоящий
`reasoning_effort` выбранной модели. Если соответствующего слова нет, он
выбирает минимальный поддерживаемый уровень не ниже запрошенного. Выше
диапазона модели используется её максимальный уровень. Это монотонное
сопоставление: увеличение `/effort` не уменьшает effort провайдера.

| Канонический набор модели | `/effort low` | `medium` | `high` | `xhigh` | `max` |
|---|---|---|---|---|---|
| low / medium / high / xhigh / max | low | medium | high | xhigh | max |
| low / medium / xhigh — Qwen 3.8 | low | medium | xhigh | xhigh | xhigh |
| low / medium / high — GPT-OSS | low | medium | high | high | high |
| low / high / max — DeepSeek V4, GLM 5.3, Kimi K3 | low | high | high | max | max |
| high / max — GLM 5.2 | high | high | high | max | max |

Например, у трёхуровневой модели low/high/max значение medium выбирает high,
поскольку это ближайший доступный уровень не ниже medium; xhigh выбирает max.
Равенство нескольких положений ожидаемо: шлюз не создаёт отсутствующие у
модели бюджеты. Если в API-запросе поле `output_config.effort` отсутствует
или содержит `auto` / `default`, шлюз выбирает реальный максимум. Сам клиент
может разрешить свой `auto` в конкретный уровень до отправки; в этом случае
шлюз обрабатывает реально полученное значение и не выдумывает его происхождение.

Документированные дополнительные алиасы сохранены: у GLM 5.2 `none` и
`minimal` выключают thinking; у Qwen 3.8 Flash `none` выключает thinking,
`minimal` соответствует low. Они не добавляются как фиктивные уровни в
штатный селектор Claude. При выключении используются реальные флаги модели,
а `preserve_thinking` / `clear_thinking=false` сохраняются. У Qwen поле
`thinking_budget` убирается, когда оно документированно несовместимо с
`reasoning_effort`.

У Qwen 3.6, Qwen 3.7, Kimi K2.x, MiniMax M2.5 и других моделей может не быть
документированного дискретного effort. Все стандартные положения Claude
принимаются без ошибки, но оставляют модельный thinking preset неизменным.
Шлюз не отправляет выдуманный `reasoning_effort` и не назначает произвольные
числовые `thinking_budget` без подтверждённых границ и семантики. В gateway
metadata `neuraldeep.claude_effort` значения `adjustable=false` и
`no-documented-discrete-effort` прямо показывают это
ограничение. Имеющийся явный параметр пользователя в модельном preset
сохраняется.

Старые сохранённые маршруты `~effort` ещё разрешаются для совместимости и
задают fallback только при отсутствии effort в запросе. Явный штатный
`/effort` имеет приоритет, чтобы старая сессия не блокировала переключение.
Новые picker/discovery их не публикуют;
обычный выбор модели использует base ID и штатный переключатель.

Сопоставление и проверки: `neuraldeep_claude/effort.py`, `tests/test_effort.py`.
Базовые профили и доказательства возможностей провайдера:
[research-efforts.md](research-efforts.md). Принятый HTTP-параметр не является
доказательством конкретной глубины reasoning у закрытого провайдера.

## Живая проверка штатного CLI

2 ноября 2026 оригинальный CLI 2.1.316 выполнил пять запросов к base route
`nd/qwen3.8-27b@subscription`, без `~effort` в имени. Использовался родной
параметр `--effort`, отдельный `CLAUDE_CONFIG_DIR` на каждую проверку,
отключённые только в диагностике tools/MCP и не больше двух одновременных
запросов. Пользовательские настройки и production-бюджеты не менялись;
фильтры, proxy-обёртки и network namespace не использовались.

| Параметр native CLI | Gateway получил | NeuralDeep получил | Ответ |
|---|---|---|---|
| `--effort low` | low | low | Точный контрольный marker |
| `--effort medium` | medium | medium | Точный контрольный marker |
| `--effort high` | high | xhigh | Точный контрольный marker |
| `--effort xhigh` | xhigh | xhigh | Точный контрольный marker |
| `--effort max` | max | xhigh | Точный контрольный marker |

Все пять native процессов завершились с exit 0, `is_error=false` и usage
исходной Qwen subscription-модели. Gateway-журнал независимо подтвердил
`effort_requested` и `effort_applied`. Для привязки при параллельной проверке
Desktop использовались уникальные диагностические `max_tokens=4091…4095`
и временное окно процесса; эти пределы не перенесены в рабочие settings.
Время каждого запроса — от 1,95 до 5,46 секунды.

Receipt: `.local/effort-validation/20261102T185308767872Z/receipt.json`.
Повторение:

```sh
python scripts/probe-effort.py
python scripts/probe-effort.py --execute --workers 2
```

Это реальная проверка native option, body и ответа сервиса. Она не является
интерактивной проверкой команды `/effort` или сохранения её предпочтения в UI,
а также не доказывает внутренний reasoning budget закрытой модели.

## Дополнительная интерактивная проверка `/effort`

В отдельном настоящем CLI TTY затем выполнена команда `/effort medium`.
Нативный клиент подтвердил `Set effort level to medium (saved as your default
for new sessions)` и сохранил значение в
`modelSettings.nd/qwen3.8-27b@subscription.effortLevel` собственного приватного
профиля. Следующий пользовательский запрос получил точный ответ
`ND_INTERACTIVE_EFFORT_MEDIUM_OK`; у соответствующего gateway-запроса
`effort_requested=medium` и `effort_applied=medium`.

Доказательства: native JSONL transcript, журнал TTY и
`.local/effort-validation/20261102T185308767872Z/interactive-2/acceptance-review.json`.
Сохранён исходный FAIL диагностического parser: он ошибочно ожидал глобальный
`effortLevel`, обычные пробелы в cursor-positioned terminal output и одинаковый
effort всех вспомогательных запросов CLI. Review отдельно связывает основной
ответ с уникальным gateway `message_stop` по времени native assistant record,
проверяет настоящий per-model параметр и native command acknowledgement.
Исходные файлы не заменены; review содержит их SHA и не отправлял новых запросов.

Без какого-либо capability override также проверены настоящие команды
`/effort max` и `/effort xhigh`. Обе приняты без понижения уровня:
max действует в текущей сессии, xhigh сохраняется как default этой модели.
Это штатная особенность CLI 2.1.316: max не является сохраняемым default;
low/medium/high/xhigh сохраняются в `modelSettings`.
Receipt: `.local/effort-validation/20261102T185308767872Z/interactive-capabilities/receipt.json`.
Эта последняя проверка не отправляла пользовательского inference-запроса.

Все интерактивные действия выполнялись в собственном `CLAUDE_CONFIG_DIR` и
созданном для теста каталоге. Основные настройки пользователя и Desktop не
менялись, процессы Desktop не закрывались.
