# Сервисы NeuralDeep в Claude через MCP

Общий адаптер использует только Python 3 и стандартную библиотеку. Код одинаков
для Linux, Windows и macOS. Каждый сервис запускается отдельным MCP-процессом;
все обращения выполняются напрямую с `urllib.request.ProxyHandler({})`, без
HTTP(S)/SOCKS-прокси из окружения. Ключи читаются в момент вызова из одного `.env`.
Они не записываются в MCP-конфигурацию, командную строку или логи.

| Группа | Инструменты |
|---|---|
| `search` | Интернет, чтение страницы, обход сайта, поиск Telegram, квота |
| `ocr` | Загрузка документа, статус, результат, квота/баланс |
| `images` | Генерация, правка нескольких файлов, ×4, фон, enhance, аватар, очередь, статус, результат, квота |
| `music` | Lyria, список моделей, статус, скачивание трека, квота |
| `tts` | Озвучка WAV, голоса, лимиты |
| `transcription` | Whisper/GigaAM, языки, подсказки, тайм-коды, лимиты |
| `diarization` | Разметка спикеров, RTTM, квота |
| `embeddings` | Все модели эмбеддингов, размеры, форматы, лимиты |
| `rerank` | Реранжирование документов, лимиты |
| `pii` | Обезличивание, восстановление из mapping, квота |
| `decisions` | FRIDA/clef-flash, выбор/шкала/да-нет/ранжирование, квота |
| `book` | Список книг, оглавление, главы, гибридный поиск |
| `speechcore` | Длинные записи, загрузка ≤2 ГБ, разметка спикеров, статусы, расшифровка, экспорт JSON/TXT/SRT/VTT/TSV/DOCX/PDF/оригинала, список, usage |
| `drift` | Агент, чаты, история, загрузка файлов, задачи, память |

Все группы изначально включены. Пример прямого запуска (в Windows вместо
`python3` обычно `py -3` или Python из установленного окружения):

```sh
python3 -m neuraldeep_claude services list
python3 -m neuraldeep_claude services disable music drift
python3 -m neuraldeep_claude services enable images
python3 -m neuraldeep_claude services enable all
python3 -m neuraldeep_claude services config
```

Последняя команда выводит фрагмент `mcpServers` для включённых сервисов с
абсолютными путями. При переносе на другой компьютер заново выполните установку
или генерацию конфигурации: абсолютные пути не переносятся. Отдельный сервер
можно проверить напрямую:

```sh
python3 neuraldeep_claude/services.py --root . mcp search
```

Настройки находятся в `.local/services.json` в виде
`{"enabled":{"search":true,"music":false}}`. Неуказанные группы включены.
Отключение действует и для уже запущенного MCP-процесса: он скрывает инструменты
при `tools/list` и отклоняет их вызовы. Чтобы интерфейс Claude перечитал список
инструментов, переподключите соответствующий MCP-сервер или запустите новую сессию.

Каждый инструмент снабжён описанием задачи, полями JSON Schema, ограничениями
сервиса и инструкциями по асинхронным операциям. Дополнительные документированные
параметры передаются через объект `parameters`, без произвольных локальных
ограничений на доступные параметры сервиса. Файлы отправляются потоково, поэтому
загрузка SpeechCore до 2 ГБ не требует держать весь файл в памяти.

## Ключи и оплата

По умолчанию каждый инструмент (кроме Drift) использует
`NEURALDEEP_API_KEY_SUBSCRIPTION`. Явное `billing="wallet"` выбирает
`NEURALDEEP_API_KEY_WALLET`. При ошибке квоты адаптер не меняет ключ и не
повторяет платный запрос. Статус и результат задачи надо запрашивать с тем же
`billing`, с которым задача была создана.

У NeuralDeep есть собственная серверная политика списания: документация
транскрибации и SpeechCore говорит, что при исчерпании бесплатной/подписочной
квоты сервер может списывать средства с кошелька владельца ключа. Выбор ключа
подписки в адаптере не отменяет эту политику провайдера. Перед загрузкой проверьте
`transcription_limits` или `speechcore_usage`; запретить такие списания можно
только настройками самого ключа/аккаунта, если сервис их предоставляет.

Drift использует отдельный токен `dft_*` и требует оплаченной подписки Drift.
Если он нужен, добавьте **в тот же `.env`**:

```dotenv
NEURALDEEP_DRIFT_TOKEN=dft_...
```

Обычные два `sk-*` ключа не заменяют Drift-токен. Без него инструменты Drift
сообщают, какой именно параметр отсутствует. Возможности веб-интерфейсов, для
которых NeuralDeep не документирует API (например, SpeechCore realtime), адаптер
не выдаёт за реализованные. Экспорты SpeechCore используют API-пути из `links`
реального ответа завершённой транскрипции; TXT/SRT/VTT/TSV/DOCX/PDF/JSON проверены
живыми скачиваниями 2 ноября 2026 года.

## Асинхронные задачи и файлы

1. Создать задачу: `image_generate`, `music_generate`, `ocr_extract`,
   `speechcore_upload`.
2. Полученный ID передать в соответствующий `*_status`. Для OCR опрашивать не
   чаще одного раза в секунду; для изображений/музыки/длинных записей разумно
   ждать несколько секунд между запросами.
3. После успешного статуса вызвать `*_result`. Изображения/аудио сохраняются в
   `.local/artifacts/` с уникальным именем, возвращаются абсолютный путь, MIME и
   число байтов. JSON/markdown возвращаются текстом. HTTP 202 не создаёт пустой
   файл, а возвращает `status=pending`.

Бинарные файлы скачиваются только с API-ручек NeuralDeep. Автоматические
перенаправления HTTP отвергаются, чтобы ключ не уходил на другой хост.
Автоматических повторов создания задач нет: после таймаута сначала проверяйте
результат у провайдера. OCR поддерживает `idempotency_key`; один ключ используйте
при безопасном повторе одного и того же запроса.

## Проверка и границы доказательств

`python3 -m unittest discover -s tests -p test_services.py -v` проверяет выбор
ключа, отсутствие прокси, отсутствие ретраев/перехода на кошелёк, выключение
групп, MCP JSON-RPC, потоковый multipart, SpeechCore query options, кодирование
ID, редактирование нескольких файлов, сохранение бинарных результатов и
маскирование ключей в ошибках. Эти тесты не расходуют квоту и не доказывают
доступность живых GPU или наличие квот у аккаунта. Живые платные пробы следует
фиксировать отдельным отчётом с моделью, ключом/режимом (без секрета), временем,
HTTP-статусом, задачей и результатом.

2 ноября 2026 года выполнены живые **читающие** пробы ключом подписки: квоты
поиска/OCR/картинок/музыки/диаризации/PII/decisions, лимиты STT/эмбеддингов/реранка,
голоса TTS, список книг, SpeechCore usage. Все 13 ручек ответили успешно.
Отчёт: `.local/service-probes.json`. Это подтверждает авторизацию и доступность
этих ручек в момент проверки; генерация, OCR и обработка аудио этими читающими
пробами не проверялись. После разрешения пользователя выполнены отдельные
функциональные платные проверки: см. `docs/VALIDATION-services.md` и
`.local/service-smoke.json`. Drift не проверялся: отдельного токена в `.env` нет.

Повторить читающие пробы:

```sh
python3 -m neuraldeep_claude services probe
```

Для проверки реальных операций есть отдельный явно запускаемый smoke-тест:

```sh
# Только план: НИКАКИХ обращений к сервису.
python3 -m neuraldeep_claude services smoke --groups all

# Явно выполнить операции и потратить квоты подписки.
python3 -m neuraldeep_claude services smoke --groups all --execute

# Явно выбрать платный ключ кошелька для этих групп.
python3 -m neuraldeep_claude services smoke --groups images music --billing wallet --execute
```

Smoke выполняет одну базовую операцию каждой выбранной группы, проверяет
основную структуру ответа и сохраняет ответы, ID задач и итог в
`.local/service-smoke.json`. Для OCR создаёт PDF с известной фразой и проверяет
её присутствие в результате. Для аудиогрупп можно указать `--audio-path`; без
этого будет одна дополнительная генерация TTS для тестовой записи. После
создания задачи запрос не повторяется; статусы опрашиваются раз в 2 секунды,
`--wait-seconds 600` задаёт время ожидания каждой задачи. При таймауте ID
сохраняется, чтобы продолжить опрос без повторного списания за создание.
Такой smoke проверяет базовый сценарий и форму ответа, а не качество всех
моделей и не все варианты параметров. Запись файла с результатом подтверждает
скачивание; корректность изображения/музыки оценивайте отдельно.
