# Наблюдения для NeuralDeep

Проверено 2026-11-02. Ключи и токены в этот документ не включены. Сообщение в поддержку автоматически не отправлялось.

1. **Qwen ∞:** `/v1/limits` сообщает активную опцию `qwen_unlim_xl` и четыре ID, но `/v1/models` их не перечисляет. Вызов каждого из четырёх ID ключом подписки вернул HTTP 401 «модель не входит в тариф этого ключа». В кабинете этого ключа Qwen ∞ XL включена, «Все модели» выбрано. Нужны корректные API-ID и объяснение отказа.
2. **Устаревший alias:** `/v1/models` включает `qwen-flash-next-ru` без type/capabilities/limit; его вызов вернул 404. Каноническая `qwen3.8-flash-next-ru` успешно работает обоими ключами.
3. **Effort Qwen 3.8 27B:** `/docs/chat.md` разрешает low/medium/xhigh, страница модели заявляет принудительный low. Все три значения принимаются и завершают короткую пробу, но применение уровня не раскрывается. Требуется единая семантика и, желательно, echo применённых параметров.
4. **Avatar:** корректный фронтальный мужской портрет, multipart `photo`, `gender=male`, `style=professional` вернул 422 `image avatar failed`. Документация не перечисляет допустимые gender/style. Нужен успешный минимальный пример.
5. **Image edit:** документация предлагает поле `images[]`, а сервер ответил 422 missing body.images. С полем `images` запрос завершился и реально изменил цвет объекта. Адаптер исправлен под сервер.
6. **Неполные limits:** ряд чат-моделей не содержит `limit.output`; у Haiku номинальный context 1M расходится с отдельно описанным ограничением входа около 90k. Нужны машинные effective input/output/context caps по ключу.
7. **Долгие агентные запросы:** в отдельных реальных CLI-запусках возникал HTTP 504 или ожидание ответа существенно дольше коротких API-проб. Успешные отдельные тесты Workflow/compact/parallel сохранены вместе с неудачными; универсальная причина задержек не установлена.
8. **Haiku 5.5 и большой контекст.** 3 ноября Desktop Code получил upstream HTTP 500 `unhashable type: 'dict'` после третьего результата Bash. Повтор восстановленной истории вернул явный HTTP 400 о пределе около 90k токенов. Запрос прошёл после сокращения только последнего результата Bash. Смена effort и снижение выходного бюджета не устранили отказ. Шлюз переводит точное сообщение о пределе в `Prompt is too long` для штатного распознавания Claude Code. Для Haiku настроено минимальное разрешённое клиентом окно автосжатия 100k, к которому клиент применяет собственный резерв. История исходной ошибки и повтор сохранены локально. Внутренняя причина первоначального исключения на стороне провайдера неизвестна.

Доказательства: `.local/model-probes.json`, `.local/new-effort-probes.json`, `.local/provider-account-observation.json`, `.local/validation-services-20261102/`, `.local/cli-validation/`. Смотрите также публичные отчёты VALIDATION-models.md, VALIDATION-services.md и VALIDATION-cli.md.
